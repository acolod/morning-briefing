## Part 2: Functional Review — Codex Findings

### 🔴 HIGH: Zero-keyword articles default to hermetic_agents
- **Issue:** `_score_article` in `rank.py` initializes `best_category = "general_ai"` with `best_score = float("-inf")`. When no keywords match, the first category in iteration (`hermetic_agents`) wins the tie because its keyword_score (0) > float("-inf"). An article about cooking could get ranked as "hermetic_agents" with a score of 0.
- **Fix:** Change default to `best_category = "general_ai"` with `best_score = 0`. Only accept a category if `score > best_score` AND `score > 0`.

### 🔴 HIGH: No delivery mechanism code
- **Issue:** The `briefing/` package only produces HTML. There is no built-in delivery (email, file write, webhook, Telegram). The cron prompt handles delivery externally.
- **Severity:** High in the sense that the package can't stand alone without the cron orchestrator.
- **Note:** Acceptable for v1 since Hermes cron handles delivery. Add a CLI `--output FILE` option for standalone use.

### 🟡 MEDIUM: Same-story cross-source duplicates
- **Issue:** `gather.py` deduplicates by URL only. The same story published on two different sites (e.g., "OpenAI launches new model" on TechCrunch AND Ars Technica) ranks twice.
- **Fix:** Add title-similarity dedup in `rank.py` before scoring (e.g., fuzzy matching or TF-IDF cosine similarity on normalized titles).

### 🟡 MEDIUM: Extracted empty dates can overwrite valid search dates
- **Issue:** `gather.py` merges `{**search_meta, **extracted_meta}`. If `web_extract` returns `{"date": None}` or `{"date": ""}`, it overwrites the valid date from the search result with None.
- **Fix:** In the merge, only use extracted values if they are non-empty: `{k: v or search_meta.get(k) for k, v in extracted_meta.items()}`

### 🟡 MEDIUM: Extraction happens before any ranking prefilter
- **Issue:** `gather()` calls `extract_fn(tuple(search_index.keys()))` on ALL unique URLs before ranking. If 40+ URLs are found, all 40 are extracted. Cost scales with search volume.
- **Fix:** Add an optional prefilter step: score articles from search metadata (title + description) first, extract only the top N candidates.

### 🟢 LOW: config/momentum loading not fault-tolerant
- **Issue:** If `momentum.json` or `config.yaml` has a YAML parse error, `load_config`/`load_momentum` raises an unhandled exception. The build crashes with no error output written.
- **Fix:** Wrap in try/except with a fallback to defaults + warning.

### 🟢 LOW: No atomic output writer
- **Issue:** The `main()` function does `print(html)`. If the redirect to file fails (disk full, permissions), the HTML is lost. No file-writing function exists in the package.
- **Fix:** Add `--output FILE` flag that writes atomically via tempfile + rename.

## Part 3: Pipeline Robustness — Codex Findings

### 🔴 HIGH: search_fn / extract_fn failures abort entire gather step
- **Issue:** If one of 6 search queries fails (network error, timeout), `gather()` raises/returns partial results. There is no partial-success handling or retry logic.
- **Fix:** Add per-query try/except with logging. Failed queries contribute 0 results instead of aborting.

### 🔴 HIGH: Malformed articles JSON aborts the build
- **Issue:** `_load_articles` in `build.py` has no try/except. If the JSON file is truncated, malformed, or missing, the entire build crashes.
- **Fix:** Wrap `json.load()` in try/except, return partial results or fall back to demo mode.

### 🟡 MEDIUM: No monitoring/alerting on failure
- **Issue:** If a daily brief fails (search timeout, build error, delivery error), there is no alert. The cron job's `last_status` field would show an error, but nobody checks it.
- **Fix:** Add a watchdog: if the cron job fails 3 days in a row, send an alert message to the user.

### 🟡 MEDIUM: No archive index
- **Issue:** Brief files are created as `brief-YYYY-MM-DD.html` but there's no `index.html` or archive page that lists/references past briefs.
- **Fix:** Add a post-build step that updates an `archive.json` with links to each brief.

### 🟢 LOW: No directory creation safety
- **Issue:** If the output directory doesn't exist, the redirect `>` silently fails or creates a file with the wrong path.
- **Fix:** The cron prompt uses explicit `cd` — acceptable for now. Add `os.makedirs` to `--output FILE` mode when implemented.

### 🟢 LOW: Imports depend on cwd
- **Issue:** `python -m briefing.build` requires the package to be installed or `PYTHONPATH` to include the parent directory. The template path in `render.py` uses `Path(__file__).resolve().parent.parent / "templates"` which is resilient. But the cron prompt's `cd ~/morning-briefing` is necessary.
- **Fix:** This is fine for the current setup. Document the requirement.

### ✅ Passing checks
- Template path resolution uses `__file__` — resilient ✅
- Package installed via pip (`pip install -e .`) ✅
- Cron job `enabled_toolsets` set to reduce token overhead ✅
