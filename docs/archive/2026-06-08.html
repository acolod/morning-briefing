arXiv ADOPT

Attack-selection blind spots are now a real eval bug, not a theoretical one

This paper matters because it shows how easy it is to flatter an agent-safety result when the attacker is modeled too politely. If the benchmark assumes attacks arrive at fixed times instead of strategically chosen moments, the reported safety level can look materially better than what a live system would face. For Hermes and coding-agent work, that means pass-rate dashboards are no longer enough; the harness itself has to model adversaries that wait for the highest-leverage moment. The useful shift here is from measuring generic competence to measuring how brittle your workflow becomes when the environment is allowed to be opportunistic.

why_now: You are already building long-horizon agents on Linux with real tools, so this is an eval-design upgrade you can apply immediately instead of just filing away as safety theory.

Hacker News ADOPT

Declarative skills look like the right default for Hermes-style workflows — but only if retrieval stays sharp

This paper is unusually aligned with how you already build: natural-language skill files, tool-use workflows, and lightweight orchestration instead of elaborate state machines. The catch is the important part: skills help when retrieval is good, but they do not rescue weak context, which is exactly the warning signal to keep your Hermes skill surface simple while investing harder in context selection and evidence quality.

arXiv TRY

SentinelBench is a better fit than another sprint-style benchmark because it tests agents that mostly wait, watch, and react

A lot of benchmark work still over-rewards agents that constantly push forward, but many of your real workflows are monitors, cron jobs, and browser tasks that need patience more than aggression. SentinelBench looks worth a trial because it tests whether an agent can notice meaningful external changes and act at the right time instead of just generating busywork.

Intuned TRY

Intuned is one of the cleaner browser-automation products to watch because it treats maintenance as the product, not an afterthought

The interesting part is not 'AI writes Playwright' — everybody says that now. The useful part is that Intuned wraps the runtime, traces, logs, scheduling, and self-healing loop around browser automations, which is exactly where headless web tasks usually become operationally annoying. That makes it worth a bounded experiment if you want a faster path for browser-only jobs without building another pile of maintenance glue yourself.

arXiv TRACK

Queen-Bee is a strong signal that MCP-era orchestration is converging on governed execution, not just more tools

The paper's value is not the bee branding; it is the architecture shape: capability retrieval, structured task compilation, tenant-scoped connectors, and explicit governance boundaries. That is the right direction for judging future orchestration systems, especially if Hermes grows from personal operator tooling into something that coordinates more services and identities.

arXiv TRACK

OpenAgenet / OAN is worth tracking as the trust layer people will want before A2A and MCP become truly open networks

A lot of protocol discussion is still focused on message shape, but OAN is focused on the uglier precondition questions: identity provenance, discovery authorization, freshness, and signed invocation. If agent-to-agent communication keeps expanding, those trust primitives will matter more than whichever protocol wins the syntax argument.

arXiv TRACK

PROBE is a reminder that post-failure recovery needs structure, not just better logs

This paper's telemetry → diagnosis → guidance split matches a real pain point in coding agents: even when you can see the failure, the recovery step is usually mushy. For Hermes and Codex workflows, it is a good architecture prompt to separate failure capture from the bounded next action you actually allow the agent to attempt.

arXiv NOTE

Measuring Agents in Production is a healthy antidote to the fantasy that real systems are giant autonomous loops

The headline result is calming: most production agents are still fairly short-horizon, heavily human-evaluated, and built with prompting rather than elaborate fine-tuning. That lines up with your operator instincts and is useful context whenever a new paper or startup implies the only serious path forward is maximal autonomy.

arXiv NOTE

Communication-graph leakage is becoming the overlooked security problem in agent interoperability

This is one of the better reminders that encrypted content is not the whole story once agents start coordinating across services. If metadata alone can leak task class and workflow intent, then future Hermes-to-agent or A2A designs will need to think about transport privacy and timing patterns much earlier than most toy demos do.
