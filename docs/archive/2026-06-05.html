Anthropic ADOPT

Anthropic open-sourced a practical reference harness for autonomous code security work

This is the rare agent-security release worth reading as an operator instead of as marketing: Anthropic published both a write-up and a reference harness for threat modeling, scanning, triage, reporting, and patching. For Hermes, the valuable pattern is not 'let an agent roam your repo,' but the staged loop: bootstrap a threat model, force evidence gathering, separate find from triage, and emit structured outputs a human can audit. That shape maps cleanly onto Codex- and cron-driven repo maintenance, and it gives you a better starting point for security automation than inventing the workflow from scratch.

why_now: You are already building automation around repos and tools, so stealing a proven agent-security loop now is higher leverage than reading another generic agent benchmark.

ArXiv TRY

Description-Code Inconsistency in real MCP servers is now measured, not hypothetical

This paper studies 19,200 description-code pairs across 2,214 MCP servers and reports inconsistencies in nearly 10% of them. The practical takeaway for Hermes is simple: treat tool descriptions as untrusted metadata and add a lightweight declared-capability versus actual-side-effects audit before depending on a new server.

ArXiv TRY

Memory poisoning has matured into a real architectural warning for agent builders

The important result here is not merely that memory can be attacked, but that aggressive write-and-retrieve patterns make agents materially more exploitable and current prompt-injection defenses do not cover the problem. That should push Hermes toward stricter memory write rules, provenance, and review points for anything long-lived.

ArXiv TRY

Evidence tracing and execution provenance are becoming first-class agent primitives

This survey matters because it frames a missing systems layer: which tool output, memory item, or retrieved fact actually caused an agent action. For Hermes, that argues for better logging around tool calls and memory lineage so debugging and trust are based on traces instead of vibes.

ArXiv TRACK

memorywire is an early but sensible attempt at a vendor-neutral memory interface

If you expect Hermes memory to evolve across backends and experiments, a common wire format is more interesting than yet another bespoke memory framework. I would not replatform around this yet, but I would track it as a reference for how to make memory operations inspectable, portable, and governable.

ArXiv TRACK

OpenAgenet suggests trust and discovery may split off from protocol execution

OAN is still early, but the framing is strong: MCP and A2A may handle interaction while separate layers handle identity, discovery, authorization, and trust evidence. Since you care about agent-to-agent coordination, this is worth tracking as the 'DNS plus package-signing layer for agents' idea.

ArXiv NOTE

Tangram is a useful signal that KV-cache wins are shifting from papers to serving systems

The interesting part is not the compression idea alone, but the systems work to make non-uniform KV caches practical without fragmentation and scheduling pain. For your local inference stack, this is a reminder that context-length improvements may come from serving engineering before they come from a new favorite model.

ArXiv TRACK

Agents' Last Exam is closer to the kind of benchmark you should actually care about

ALE focuses on long-horizon, economically meaningful workflows with verifiable outcomes, and current systems reportedly average only a 2.6% full-pass rate on the hardest tier. That makes it a good north-star reference for Hermes eval design: fewer trivia benchmarks, more durable workflow tests.
