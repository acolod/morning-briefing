ArXiv Agents ADOPT

Contract2Tool turns vague tool registries into something an agent can actually reason about

This is the most directly usable idea in today's pile because it targets the real bottleneck in Hermes-style systems: not whether a tool exists, but whether the agent can tell when it is appropriate, risky, and likely to change task state. The paper's framing around preconditions, effects, risk, and cost maps cleanly onto MCP-era tool surfaces and is more relevant to your stack than generic 'tool use got better' claims. The token-reduction result is interesting, but for you the bigger win is better tool routing and fewer bad tool choices inside long-running workflows. If you keep Hermes browser-first and approval-aware, richer tool contracts are the kind of boring infrastructure that could quietly improve quality across the whole system.

why_now: You already have a structured tool layer, so adding contract metadata is a near-term architecture upgrade rather than a speculative research note.

ArXiv Benchmarks ADOPT

WeaveBench is a much closer match to real operator work than another single-interface agent benchmark

This one matters because it mixes GUI, shell, editor, browser, and file checks in the same trajectory, which is much closer to Hermes-plus-Codex reality than toy browser tasks. I would treat it as an eval design reference now, especially because it shows outcome-only grading overstates competence.

ArXiv Systems TRY

Syll is one of the more interesting open-source personal-agent runtimes because it externalizes skills, memory, and governance as local artifacts

The strongest overlap is architectural, not product-level: teachable procedures, reusable skills, multimodal evidence, and editable local state. It is worth a bounded read because it rhymes with Hermes in the places that matter, even if its GUI-heavy validation means it is not an immediate drop-in for your headless setup.

ArXiv AI TRY

RunAgent SuperBrowser is a plausible browser-agent pattern to borrow from even if you never touch the product itself

The useful idea here is the architecture split: vision-first target finding, small structured ledger, and cleaner separation between orchestration and step execution. For your browser-first workflows, that is a better signal than headline benchmark chest-thumping.

ArXiv AI TRY

Scaffold Effects on GAIA is a good reminder that workflow claims about Codex, Claude, or Gemini are often harness claims in disguise

A 28-point swing from scaffold choice alone is a healthy warning against over-reading model-vs-model comparisons. For your setup, it argues for keeping quick internal bake-offs honest by varying the scaffold before concluding that one coding tool is truly better.

ArXiv AI TRACK

vla.cpp is worth tracking as llama.cpp-style local inference expands from text into action-oriented multimodal runtimes

This is not an install-now recommendation, but it is relevant to your local-inference lane because it extends familiar llama.cpp design instincts into VLA serving. If the implementation matures, it could become a meaningful path for lightweight local multimodal experiments on constrained hardware.

ArXiv AI TRACK

SearchSwarm treats delegation as a first-class capability instead of a hand-wavy multi-agent vibe

That makes it relevant to Hermes orchestration work, especially if you keep pushing beyond single-agent workflows into bounded specialist subagents. I would watch it as a signal for how people start training or benchmarking delegation itself rather than just describing it in diagrams.

ArXiv AI TRACK

CHAP is the rare protocol paper that notices MCP and A2A still leave a gap around accountable human-agent work

The interesting part is the append-only evidence log and structured approvals/overrides, which feels closer to how durable operator systems actually need to behave. I would not bet on the spec yet, but I would track the problem framing because it is pointed in the right direction.

GitHub NOTE

This is less about novelty and more about having a durable reference point for coding, long-context, tool-use, and agent evaluation. Even if you do not adopt the stack whole, it is a good repo to keep in the folder when you want to sanity-check how serious eval platforms are evolving.
